🕵️ 국토 대탈출

“초등 5학년 사회 ‘우리 국토의 위치’를
작은 HTML 수업앱으로 만드는 7차시 바이브코딩 프로젝트”

① 프로젝트 한 문장 소개

학생이 탐정이 되어 ‘국토 대탈출’ 사건을 해결하며 국토 → 지구본·세계지도 → 위도 → 경도 → 우리나라 좌표를 단계적으로 알아보고, 마지막에는 수업 근거 자료를 폐쇄형 검색으로 확인하는 단일 HTML 수업 자료입니다.

③ 5분 시연 순서

1분

사건 시작

긴급 메시지 → 탐정 임명 → ‘국토’ 정답을 선택합니다.

2분

좌표 단서

지구본+세계지도 → 위도 → 경도를 빠르게 시연합니다.

3분

최종 좌표

북위 33~43도·동경 124~132도를 맞혀 50점을 확인합니다.

4분

근거 확인

국토·위도·경도·우리나라 좌표를 검색하고 답과 출처를 보여 줍니다.

5분

만든 과정

실제 디버깅 사례와 ‘작은 요청 → 실행 → 검증’ 과정을 소개합니다.

④ 실제 디버깅 사례 3개

사례 1 · 정답 후에도 다음 버튼이 disabled

증상: 국토를 맞혀 점수 10점과 정답 안내는 나오지만 다음 버튼이 계속 잠겼습니다.

원인: 정답 처리와 다음 버튼의 잠금 상태를 연결하는 상태값이 제대로 갱신되지 않았습니다.

수정: 정답 처리에서 해당 장면을 완료 상태로 만들고 화면 갱신 시 다음 버튼의 disabled 상태를 다시 계산했습니다.

배운 점: “정답 표시”와 “다음 단계 잠금 해제”는 별개의 상태이므로 둘 다 검증해야 합니다.

사례 2 · 무료 출력 한도로 facts 중간에서 HTML이 잘림

증상: 지구본 answer 문자열 중간에서 출력이 끝났고, 닫는 script/body/html과 기존 이동 로직까지 사라졌습니다.

원인: 한 번에 너무 많은 코드를 생성하여 무료 버전의 출력 한도를 넘었습니다.

수정: 기능을 유지하면서 CSS와 문구를 압축하고, 13,000자 이하의 완전한 단일 HTML로 다시 작은 요청을 보냈습니다.

배운 점: 바이브코딩에서는 한 번에 최종본을 요구하기보다 차시별 범위를 지키고, 작은 수정 단위로 생성·실행·검증하는 것이 중요합니다.

사례 3 · 이모지와 쉼표 때문에 정답 비교 실패

증상 A: `🌐 지구본`, `🗺️ 세계지도`를 눌러도 정답이 아니라고 판정되었습니다.

원인 A: 버튼의 textContent에는 이모지가 포함되어 있어 정답 단어와 완전 일치하지 않았습니다.

수정 A: 장면 3은 버튼 텍스트에 정답 단어가 포함되는지 확인하도록 바꾸고, 두 정답을 모두 선택했을 때만 완료되게 했습니다.

증상 B: 장면 6의 좌표 정답도 오답 처리되었습니다.

원인 B: 모든 장면에 쉼표 split을 공통 적용하여 북위 33~43도, 동경 124~132도의 쉼표까지 복수 정답 구분자로 해석했습니다.

수정 B: 장면 3만 복수 선택 모드로 유지하고, 나머지 장면은 정규화한 전체 버튼 텍스트와 전체 정답 문자열을 비교하도록 분리했습니다.

배운 점: 데이터 형식이 다른 문제를 하나의 판정 로직으로 억지로 처리하지 않고, 예외가 필요한 장면의 규칙을 명확하게 분리합니다.

⑤ RAG란 무엇인가?

RAG는 질문에 답할 때 미리 준비한 자료에서 관련 정보를 찾아 답변에 활용하는 방식입니다.

이번 프로젝트에서는 인터넷의 모든 정보를 자유롭게 검색하거나 외부 AI에게 질문하지 않습니다. 수업에서 정한 근거 카드 안에서만 찾아봅니다.

핵심: “모르는 것은 그럴듯하게 만들지 않는다.”
등록된 근거와 연결되지 않는 질문에는 정해진 거절 문구를 보여 줍니다.

⑥ 이번 자료의 RAG는 어떻게 작동하는가?

이번 수업앱의 RAG는 외부 AI 호출이 없는 폐쇄형 키워드 검색입니다.

  • 근거 자료는 첨부 수업자료 「[1차시] 우리 국토의 위치를 알아봅시다(1).pptx」와 국토교통부 어린이 공식 페이지만 사용합니다.
  • 6개의 facts 카드에 keywords, answer, source, url을 저장합니다.
  • 학생의 질문과 각 카드의 keywords를 비교하여 가장 많이 일치하는 카드를 찾습니다.
  • 일치하는 카드가 있으면 답 + 출처를 보여 줍니다.
  • 키워드가 하나도 일치하지 않으면 추측하지 않고 정확히 “이 수업의 근거 자료에서는 확인할 수 없습니다.”라고 답합니다.

6개 근거 카드: 국토 정의 · 지구본 · 세계지도 · 위도 · 경도 · 우리나라 위치(북위 33~43도·동경 124~132도)

⑦ 다른 단원에 적용하는 방법

전체 프로그램을 다시 만들 필요 없이, 폐쇄형 검색의 facts 카드 내용을 새 단원의 근거 자료에 맞게 바꾸는 방식으로 확장할 수 있습니다.

핵심적으로 바꾸는 항목은 네 가지입니다.

{
  keywords: ["새 단원 핵심어", "질문어", "동의어"],
  answer: "근거 자료에서 확인한 정확한 답",
  source: "자료명 또는 공식 출처",
  url: "공식 페이지 주소"
}
주의: keywords에 없는 내용을 추측하여 answer에 넣지 않습니다. source와 url도 실제로 확인한 근거만 기록합니다. 단원의 사실이 바뀌면 먼저 원자료를 확인한 뒤 facts를 수정합니다.

즉, 수업 이야기와 화면은 유지하고 → 근거 카드의 네 항목을 새 단원에 맞게 교체하는 방식입니다.
